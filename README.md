# Spatial Detective Agency

# 空间探案局：基于空间依赖与空间自相关的沉浸式交互学习 App 

## 一、项目名称

**《空间探案局：Spatial Detective》**

副标题：  

**一款以空间依赖性、空间邻居、空间权重矩阵与空间自相关检验为核心的强情境、强互动学习 App**

---

## 二、项目背景与设计目标

空间统计与空间计量分析中的核心概念，如**空间依赖性**、**空间邻居关系**、**空间权重矩阵**以及**空间自相关检验**，往往较为抽象，传统教学通常停留在公式解释、案例演示和软件操作层面，学习者容易出现以下问题：

1. **概念理解碎片化**：知道定义，但难以真正理解“为什么空间上会互相影响”。

2. **矩阵构建机械化**：会生成权重矩阵，但不清楚不同邻接规则的含义及后果。

3. **检验结果记忆化**：能背出 Moran’s I、LISA 等名词，但不会在真实问题中判断和解释。

4. **缺乏情境驱动**：学习内容与现实空间问题脱节，缺少探索动机。

5. **缺少连续挑战与反馈**：知识点之间未形成完整任务链，互动体验不足。

因此，本方案拟设计一款以“**城市危机调查**”为主线的沉浸式 App，通过任务闯关、角色扮演、实时地图交互、推理挑战、多分支决策和成就认证机制，将抽象的空间统计知识转化为可感知、可操作、可解释的学习体验。

### 设计目标

- 将空间统计核心概念转化为**情境任务**

- 通过多轮交互让学习者真正理解**空间关系构建逻辑**

- 让学习者在“做中学”中掌握：

  - 空间依赖性识别

  - 空间邻居判定

  - 空间权重矩阵构建

  - 全局与局部空间自相关检验

- 形成“**学习—挑战—反馈—认证**”闭环

- 最终为完成全部任务的学习者颁发**数字证书**

## 四、产品核心定位

该 App 不仅是一个“知识展示工具”，更是一个**剧情驱动式互动学习平台**。  

用户在应用中扮演“**空间调查员**”，接受来自不同城市部门的任务，调查城市中出现的异常空间现象，例如：

- 某些街区房价异常集聚

- 某区域传染病病例快速扩散

- 城市热岛呈片状分布

- 犯罪率在局部地区持续聚集

- 电商配送延误呈空间扩散特征

用户必须通过对空间数据的观察与分析，逐步完成：

1. 判断是否存在空间依赖性  

2. 确定谁与谁是空间邻居  

3. 构建合适的空间权重矩阵  

4. 进行空间自相关检验  

5. 对检验结果作出空间解释  

6. 提交分析报告并获得评级

# 五、总体叙事情境设计

## 1. 故事设定

在未来智慧城市“**新域市**”中，城市管理系统频繁监测到一些异常分布事件。市政府成立了“空间探案局”，专门处理一切与“空间关联异常”有关的案件。玩家作为新入职的“空间调查员”，将接受不同部门委托，深入调查城市运行中的空间现象。

## 2. 情境案件模块

每一章是一个独立故事，同时又组成总线剧情：

### 案件一：热力失衡

市环保局发现城市温度并非随机分布，而是形成多个高温团块。  

用户需判断是否存在**空间依赖性**，并分析热岛聚集是否显著。

### 案件二：疫情蔓延

某疾病在相邻社区之间有传播迹象。  

用户需构建**空间邻居关系**，比较不同邻居定义对扩散判断的影响。

### 案件三：房价迷局

房价高值区与低值区似乎呈现稳定团块。  

用户需尝试构建不同的**空间权重矩阵**，解释矩阵选择对结果的影响。

### 案件四：治安黑洞

部分街区犯罪率持续偏高。  

用户需进行**全局 Moran’s I** 与 **局部 LISA** 分析，锁定热点与异常区。

### 案件五：交通拥堵链

拥堵不是单点问题，而是沿道路网络传导。  

用户需理解不同空间结构（面邻接、距离邻接、网络邻接）下空间依赖的差异。

### 终极任务：城市风险总指挥

用户整合所有案件中的方法，对一份综合城市数据进行完整空间分析，输出最终报告，解锁证书。

# 六、核心知识模块与内容映射

| 理论知识 | App中对应机制 | 互动形式 |

|---|---|---|

| 空间依赖性 | 观察异常空间分布、识别非随机性 | 热图拖拽、区域点击、假设判断 |

| 空间邻居 | 确定区域之间的邻接关系 | 画边连线、邻居圈选、规则切换 |

| 空间权重矩阵 | 生成 \(W\) 矩阵并调整规则 | 拖拽构建矩阵、参数滑条、矩阵可视化 |

| 空间自相关检验 | 计算并解释 Moran’s I / LISA | 动态图表、显著性模拟、结果归因 |

| 检验结果解释 | 识别 HH、LL、HL、LH | 四象限散点图交互、地图联动 |

| 模型比较 | 对比不同矩阵或阈值下结果差异 | AB测试式闯关、反事实挑战 |

# 七、App功能架构设计

## 1. 首页：进入空间调查世界

首页采用剧情式入口：

- “进入空间探案局”

- “继续上次任务”

- “案件档案馆”

- “训练营”

- “排行榜”

- “证书中心”

首页视觉上设计为城市控制中心大屏，实时显示地图、预警事件和案件等级。

---

## 2. 模块一：空间依赖性感知实验室

### 功能目标

帮助用户从直观层面理解：  

**空间现象往往不是独立随机的，而是存在相互影响。**

### 交互设计

- 用户看到一张城市分区地图，上面显示某变量值（如房价、病例数、温度）

- 用户可切换：

  - 原始地图

  - 随机打乱后的地图

  - 平滑后的地图

- 系统提问：

  - 哪一张更可能存在空间依赖？

  - 为什么相邻区域数值更接近？

  - 如果完全独立，空间上应呈现什么样子？

### 互动挑战

1. **“找出非随机地图”挑战**

   - 3张地图中选出最可能具有空间依赖性的一张

2. **“拖动扰动”挑战**

   - 用户拖动若干区域打乱位置，观察整体聚集性如何变化

3. **“空间影响链”挑战**

   - 点击一个区域，系统动态显示其对周边区域可能造成的影响波纹

### 游戏反馈

- 回答正确可获得“空间感知值”

- 若选择错误，系统用动画解释“为什么随机分布不形成块状聚集”

---

## 3. 模块二：空间邻居判定中心

### 功能目标

使用户理解不同“邻居”定义并非唯一，不同定义会影响分析结果。

### 邻居规则内容

- rook 邻接（共边邻接）

- queen 邻接（共边或共点邻接）

- 距离阈值邻居

- K近邻

- 网络邻接（适合道路、轨道等）

### 交互设计

用户面对一张区域地图，需要根据任务要求自行定义谁是邻居。

### 互动玩法

1. **“圈邻居”任务**

   - 点选某一区域后，用户需圈出它的邻居区域

2. **“规则切换”实验**

   - 同一地图下切换 queen / rook / 距离邻接，邻居边实时变化

3. **“最合理邻居”辩论题**

   - 某情境如疫情传播、房价联动、交通流传导，用户需选择最合理邻接规则并说明原因

4. **“邻居不足补救”挑战**

   - 某些孤立区域没有邻居，要求用户调整阈值或改用 K近邻

### 强交互机制

- 地图点击后显示“邻居链路”

- 拖动距离阈值滑块，邻居数量实时变化

- 系统给出“过密/过疏”提醒

- 用户每次改变规则，地图、矩阵、统计指标同步更新

---

## 4. 模块三：空间权重矩阵工坊

### 功能目标

让用户真正理解：  

**空间权重矩阵不是黑箱，它表达的是空间单元之间影响关系的编码方式。**

### 展示内容

- 二元邻接矩阵

- 行标准化矩阵

- 距离衰减矩阵

- 自定义权重矩阵

### 交互形式

#### 1）矩阵拼装台

- 地图与矩阵并排显示

- 点选地图上的两个区域，可决定它们的权重值

- 用户自己构建一个简化版矩阵

#### 2）自动构建与人工修正

- 系统自动根据 queen、rook、距离阈值生成矩阵

- 用户可手动修改后比较分析结果

#### 3）矩阵可视化联动

- 点击矩阵某元素 \(w_{ij}\)，地图上高亮区域 \(i\) 与 \(j\)

- 点击地图上的区域，矩阵中高亮该行或列

### 互动挑战

1. **“修复错误矩阵”挑战**

   - 系统给出一个错误矩阵，让用户找出问题：

     - 非邻居却赋权

     - 漏掉真实邻居

     - 对角线错误

2. **“矩阵选择题”挑战**

   - 针对不同应用场景选择最合适的权重矩阵

3. **“参数大师”挑战**

   - 用户调整距离衰减参数，观察全局统计量变化

4. **“结果反转”挑战**

   - 找到一个矩阵设定，使原本不显著的自相关变得显著，理解方法选择的敏感性

### 教学强化

系统在每次构建矩阵后给出解释：

- 该矩阵强调的是“接触关系”还是“距离关系”

- 是否存在孤岛单元

- 是否进行了行标准化

- 对后续 Moran’s I 有何潜在影响

---

## 5. 模块四：空间自相关检验作战室

### 功能目标

让用户通过交互过程掌握：

- 全局空间自相关

- 局部空间自相关

- 显著性检验

- 结果解释与政策判断

### 内容结构

#### （1）全局 Moran’s I

- 展示公式的含义，但以可视化为主

- 用户可以拖动某一区域数值，看 Moran’s I 如何变化

- 通过置换检验动画理解显著性

#### （2）Moran散点图

- 四象限交互

- 点击某个区域，散点图和地图联动

- 用户可观察 HH、LL、HL、LH 四类区域

#### （3）局部自相关 LISA 图

- 热点区、冷点区、高-低异常、低-高异常动态呈现

- 显著性水平可调整

### 互动挑战

1. **“拉高 Moran’s I”挑战**

   - 在限定次数内调整若干区域值，使总体聚集性最大

2. **“消除异常点”挑战**

   - 通过修改少量区域值，让 HL / LH 异常区减少

3. **“真假显著”挑战**

   - 通过置换检验结果判断观察值是否真的显著

4. **“四象限缉凶”挑战**

   - 根据散点图和地图，找出 HH、LL、HL、LH 对应区域

5. **“局部热点锁定”挑战**

   - 在复杂地图中找出真正具有局部显著聚集的区域

### 强情境嵌入

比如在“治安黑洞”案件中：

- 用户不仅要算出 Moran’s I

- 还要给市长提交判断：

  - 犯罪是否存在整体聚集？

  - 哪些区域是重点巡防对象？

  - 哪些区域属于异常点，可能提示跨区影响或统计误差？

# 八、沉浸式任务系统设计

## 1. 角色系统

用户可选择角色身份：

- 城市风险分析师

- 公共卫生调查员

- 房地产市场研判师

- 环境监测专员

- 治安空间侦查员

不同角色进入不同剧情线，但核心知识框架一致。

---

## 2. 任务流程

每个案件采用统一流程：

### 第一步：接收任务

通过剧情视频/漫画/对话框获取案件背景。

### 第二步：初步观察

浏览地图、图表、简报，进行初步假设判断。

### 第三步：定义邻居

根据问题背景选择空间邻居规则。

### 第四步：构建权重矩阵

生成并检查空间权重矩阵。

### 第五步：实施检验

执行 Moran’s I / LISA 等检验。

### 第六步：解释结果

回答开放题、选择题或语音简报。

### 第七步：提交报告

系统自动评分并生成案件评级。

---

## 3. 分支剧情机制

用户的选择会影响剧情走向。

例如：

- 若错误选择邻接方式，疫情扩散模拟可能出现偏差

- 若构建权重矩阵不合理，后续政策建议会失真

- 若误判显著性，可能导致资源配置失败

这样可增强“**方法选择影响现实决策**”的感受。

# 九、交互挑战体系设计

为了满足“**富情景强交互、很多交互挑战**”的要求，App设置如下挑战层级：

## 1. 基础挑战

- 点击识别

- 拖拽匹配

- 地图圈选

- 邻居连线

- 矩阵填空

## 2. 中级挑战

- 参数调整

- 多方案比较

- 错误纠正

- 显著性判断

- 地图—图表联动分析

## 3. 高级挑战

- 限时任务

- 多轮推理

- 反事实实验

- 开放式分析报告

- 多案件整合决策

## 4. 特殊玩法挑战

### （1）限时预警模式

例如 3 分钟内判断城市哪些区域存在显著热点。

### （2）多人协作模式

多个用户组成“调查组”：

- 一人负责邻居规则

- 一人负责矩阵构建

- 一人负责检验解释

- 最后共同提交报告

### （3）对抗模式

两个小组针对同一城市数据，分别选用不同权重矩阵，比较谁的解释更合理。

### （4）盲盒数据模式

系统随机生成空间数据格局，用户必须快速判断是否存在空间自相关。

### （5）政策模拟模式

根据分析结果配置资源，如警力、医疗站、绿化带，观察城市指标变化。

- 提交一份综合空间分析报告

### 证书内容

- 用户姓名

- 完成时间

- 课程/项目名称

- 掌握能力标签

- 唯一证书编号

- 二维码验真

- 发证机构名称

### 证书等级

- 铜级：完成基础任务

- 银级：完成全部任务且总分良好

- 金级：高分通过并解锁全部隐藏挑战

- 荣誉级：多人协作与专家挑战全通过

# 十二、学习评价设计

## 1. 形成性评价

贯穿全过程：

- 每个任务节点即时评分

- 错误时给出概念提醒

- 自动记录知识薄弱点

## 2. 总结性评价

终极任务评分维度：

- 邻居规则选择是否合理

- 权重矩阵构建是否正确

- Moran’s I 结果解读是否准确

- 局部聚集区识别是否清晰

- 最终决策建议是否有逻辑

## 3. 智能反馈

# 十五、示例任务脚本展示

## 示例：房价迷局

### 背景

新域市南部多个社区房价持续上涨，媒体怀疑存在“高房价集聚泡沫”。

### 用户任务

1. 观察房价分布图，判断是否可能存在空间依赖

2. 选择 queen 邻接、rook 邻接或距离邻接

3. 生成对应空间权重矩阵

4. 计算全局 Moran’s I

5. 观察 LISA 图，锁定 HH 区域

6. 向“市住房局”提交结论：

   - 房价是否显著集聚？

   - 热点区在哪里？

   - 是否存在高-低异常区域？

   - 应采取何种调控建议？

### 可能挑战

- 若用户错误选择过大的距离阈值，会使邻接过密，分析失真

- 若遗漏孤立社区，系统要求修正矩阵

- 若误将局部异常点当作热点区，结案评分下降

本设计方案以“**空间探案局**”为叙事框架，将**空间依赖性、空间邻居、空间权重矩阵、空间自相关检验**等抽象理论转化为可沉浸、可推理、可挑战、可认证的学习过程。它不仅强化了知识掌握，更培养了学习者在真实问题中运用空间分析方法的能力。
